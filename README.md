# CRYPTO_MESSENGER // TERMINAL EDITION

Полностью криптованный мессенджер в стиле терминала. End-to-end шифрование (E2EE). Зелёный текст на чёрном фоне.

## Возможности

- ✅ **End-to-End шифрование** — сервер не может прочитать сообщения
- ✅ **Общий чат** `#global_chat` для всех пользователей
- ✅ **Личные сообщения** `@username` между любыми двумя пользователями
- ✅ **PWA** — устанавливается на главный экран
- ✅ **Терминальный интерфейс** — матрично-зелёный glow, monospace, scanlines

## Архитектура

- **Бэкенд:** Node.js + Express + Socket.io + SQLite
- **Фронтенд:** Vanilla JS PWA + Web Crypto API
- **Шифрование:** ECDH P-256 + AES-GCM 256

## 🚀 Деплой на Railway

### Шаг 1: Загрузи проект

1. Зайди на [railway.app](https://railway.app) и залогинься
2. **New Project** → выбери один из способов:
   - **Deploy from GitHub repo** — если залил этот код в свой репозиторий (рекомендуется, проще потом обновлять)
   - **Empty Project** → затем в проекте выбери **Deploy from local directory / CLI**, если хочешь без GitHub

Railway автоматически распознает Node.js-проект по `package.json` (билдер `NIXPACKS` уже прописан в `railway.json`) и выполнит `npm install`, затем запустит `npm start`.

### Шаг 2: Задай переменные окружения

В настройках проекта → **Variables** добавь:

| Переменная   | Значение                                 | Обязательна |
|--------------|-------------------------------------------|-------------|
| `JWT_SECRET` | любая длинная случайная строка            | Да |
| `PORT`       | не задавай — Railway подставит сам        | — |
| `DB_PATH`    | `/data/database.sqlite` (см. Шаг 3)       | Нет, но желательно |

Сгенерировать случайный секрет можно, например, командой `openssl rand -hex 32` у себя в терминале.

### Шаг 3 (важно): постоянное хранилище для базы данных

По умолчанию Railway пересоздаёт файловую систему контейнера при каждом деплое/рестарте — значит, файл `database.sqlite` (все пользователи и сообщения) будет **стираться**.

Чтобы этого избежать:

1. В проекте на Railway → **New** → **Volume**
2. Примонтируй его, например, на путь `/data`
3. В Variables добавь `DB_PATH=/data/database.sqlite`

После этого база будет переживать редеплои.

### Шаг 4: Домен

Railway → Settings → Networking → **Generate Domain** — получишь публичный `https://...up.railway.app` адрес. Сертификат HTTPS Railway выдаёт и продлевает сам, свой самоподписанный сертификат (`generate-cert.js`) для продакшена не нужен — он только для локального запуска.

### Шаг 5: Проверка

Открой полученный домен в браузере — должен появиться экран входа. Зарегистрируй первого пользователя — он автоматически создаёт общий чат.

## 💻 Локальный запуск (для разработки)

```bash
npm install
npm start
```

Сервер поднимется на `http://localhost:8080` (или на порту из переменной `PORT`, если задана).

Если нужен HTTPS локально (например, для тестирования на телефоне в одной сети):

```bash
npm run generate-cert
```

создаст самоподписанный сертификат в `server/certs/` (только для локальной разработки, сам сервер должен быть доработан для его использования — по умолчанию сервер поднимается по HTTP и рассчитан на то, что HTTPS обеспечивает хостинг, как на Railway).

## 🔒 Как работает шифрование

1. При регистрации на устройстве генерируется пара ключей ECDH P-256
2. Приватный ключ **никогда** не покидает устройство (IndexedDB)
3. Публичный ключ — на сервере
4. **ЛС:** ephemeral ECDH + AES-GCM для каждого сообщения
5. **Общий чат:** общий AES-ключ, передаётся новым участникам через ECIES
6. Сервер видит только шифротекст

## ⚠️ Важно

- **Первый пользователь** создаёт ключ общего чата
- **Новые пользователи** получают ключ автоматически от онлайн-участников
- **Приватный ключ не покидает устройство** — при смене телефона нужна новая регистрация
- **Обязательно задай `JWT_SECRET`** в переменных окружения Railway — без этого сервер работает на небезопасном значении по умолчанию
- **Подключи Volume и задай `DB_PATH`**, если хочешь, чтобы данные не терялись при редеплое

## 🆘 Проблемы

| Проблема | Решение |
|----------|---------|
| После редеплоя пропали все аккаунты и сообщения | Не был подключён Volume — см. раздел "Постоянное хранилище" выше |
| Ошибка сборки на этапе установки `sqlite3` | Обычно временная проблема Nixpacks с компиляцией нативного модуля — попробуй передеплоить; если повторяется, напиши мне, заменим на `better-sqlite3` |
| Не открывается сайт после деплоя | Проверь, что в Settings → Networking сгенерирован домен |
| Общий чат не работает после смены базы | Удали старый `database.sqlite` / volume-файл, перезапусти сервер, зарегистрируйся заново |
